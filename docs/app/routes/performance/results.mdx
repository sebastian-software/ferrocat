## Three different jobs

<BenchmarkResults />

- **Parse PO** reads the same 10,000-message German Gettext fixture. Ferrocat's
  displayed result uses its borrowed parser; owned parsing allocates a different
  result and should be measured separately.
- **Plain merge** combines source updates with an existing catalog. It does not
  include Ferrocat's full high-level ICU checks and placeholder tracking.
- **Full catalog update** includes those high-level checks for Ferrocat. The other
  tools have their own update semantics. GNU `msgmerge` uses the report's adjusted
  throughput, accounting for its process baseline; it is not an in-process API.

The figures are rounded medians in MiB/s. They measure these fixtures and tasks,
rather than end-to-end application build time or translation quality. Tool startup,
validation, allocation and preservation behavior can differ. No speed factor here
should be read as a guarantee for another workload or machine.
